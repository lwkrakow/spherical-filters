Module 02 · From known geometry to useful uncertainty

Learning which features to trust

Use exact simulated geometry to learn appearance sensitivity, then connect real pose uncertainty to selective trust in the tracker.

The same vehicle can look different. How much difference should we expect?

Imagine circling a parked vehicle. Its identity stays the same, but its image and embedding change. Some combinations of features change much more than others. We want the tracker to say: “We expected disagreement in these directions; use the more stable evidence more strongly.”

Calibration means learning those directions and the amount of tolerance they need. Our simulated dataset gives us an unusually useful starting point: the camera and target geometry that generated each image is known exactly.

What we know in simulation, and what we will estimate in flight

During calibration: exact geometry

The simulator supplies each image's vehicle identity and true viewing geometry. These are our labels: we can relate a known change in azimuth, elevation, or target yaw to the resulting embedding change.

We can select nearby views, or generate controlled variations, to measure the response one physical input at a time.

During tracking: estimated geometry

The drone provides estimates of camera position and orientation, together with their uncertainty. From those estimates we derive uncertainty in the viewing geometry relative to the target.

Our calibrated appearance sensitivities then help turn that physical uncertainty into directional observation noise for the filter.

The known geometry in simulation lets us learn and test the bridge. The uncertainty of real-world geometry tells us how much tolerance to apply through it.

The bridge: geometry → appearance sensitivity → observation noise

Suppose a small azimuth change moves the embedding strongly along one direction, while an equal elevation change has a smaller effect elsewhere. Those measured responses tell us where physical uncertainty will have its biggest impact.

Now suppose the drone's pose estimate leaves the relative azimuth more uncertain than elevation. We allow more appearance discrepancy along the azimuth-sensitive direction. We can keep other directions more precise, instead of broadening every feature equally.

Rₜ ≈ W Σ_view Wᵀ + R_other

W: the appearance response learned from known simulated geometry. Σ_view: uncertainty in the relative viewing angles. R_other: the remaining appearance-error allowance. Together they give Rₜ, the observation uncertainty used by the filter.

Exact simulation labels do not make appearance variation disappear. We can also measure the same-vehicle changes that our simple appearance predictor leaves unexplained, and use them to calibrate that remaining allowance.

Optional: how camera pose uncertainty enters this equation

A camera position/orientation covariance is not yet a viewing-angle covariance. First propagate it through the camera-to-target geometry to obtain Σ_view; include target position or heading uncertainty when used by that geometry. A given position error can produce different angle errors at different ranges.

W contains local appearance changes per radian. Keep those magnitudes and use consistent units. Its columns need not be perpendicular, and Σ_view may contain correlated errors. The expression is first-order uncertainty propagation. A diagonal Σ_view is a useful initial assumption to test.

The telemetry term accounts for uncertainty about geometry. Size the allowance for other unmodeled appearance changes from observed errors, avoiding double-counting. If pose uncertainty already enters through a joint state/observation model, account for it once.

Four experiments, each building on the last

1. Measure controlled responses → 2. Compare WC-TPCA and T-PLS → 3. Check the uncertainty envelope → 4. Test tracking.

Start with one embedding backbone. A reference is one vehicle at a chosen view. An appearance residual is the difference between a new embedding and that reference, described on the local tangent plane introduced in Module 01.

1. Measure one response at a time

Use: one vehicle, one reference view, and the simulator's true angle labels. Keep lighting, crop settings, and other rendering conditions fixed.

  1. Take views at a small positive and negative azimuth offset, for example ±2°, while keeping the other inputs fixed.
  2. Compute their embedding differences in the same tangent coordinates. Divide their difference by the angular separation to estimate embedding change per radian.
  3. Repeat for elevation and target yaw. This gives one named sensitivity vector per physical input: the initial columns of W.
  4. Use those vectors to estimate the appearance change for small combinations of angle offsets, then compare with the actual simulated embeddings at those held-out combinations.

Produce: three measured response vectors and a plot comparing estimated and actual appearance changes. This checks whether a simple local three-input model is a useful starting point.

Look for: which inputs have strong effects, whether their directions overlap, and how much variation remains unexplained. You can visualize their span in up to three dimensions.

Optional: what “one direction per input” assumes

The local model is v ≈ w_az δaz + w_el δel + w_yaw δyaw. Each vector can involve many embedding coordinates. The vectors need not be perpendicular or independent. If azimuth is defined relative to target heading, yaw may duplicate part of that effect; use the simulator's angle conventions consistently.

If the existing dataset lacks suitable one-input variations, generate a small controlled batch or use nearby labeled samples to fit a local relationship. Repeat the initial check at more views and vehicles before assuming that one W applies everywhere.

2. Compare WC-TPCA and T-PLS on the same observations

Use: several nearby views of each vehicle, their embeddings, and their true simulator labels. Reserve other observations for checking the result. The controlled responses from Experiment 1 give us a reference for interpreting what these methods find.

WC-TPCA · FOLLOW THE SPREAD

“Where does this vehicle's appearance vary most?”

Within-Class Tangent PCA groups observations of the same vehicle, measures their local appearance differences, and finds the directions where they spread out most.

Output: main directions and the amount of spread along each. Use them to build a baseline nuisance-uncertainty ellipse.

T-PLS · USE THE VIEWPOINT LABELS

“Which changes go with the viewing geometry?”

Tangent Partial Least Squares uses the same appearance differences together with azimuth, elevation, and other selected pose labels to learn a compact relationship.

Output: a pose-related appearance model and its remaining errors. Use that relationship to help condition uncertainty on the viewing situation.

Within-class means comparing the same vehicle across views. Tangent means describing nearby spherical differences in a local flat space. Both methods can find patterns involving many embedding coordinates.

Why compare them? If the training orbit also climbed, PCA may find a diagonal spread because the two effects occurred together. Pose labels give T-PLS extra information for relating that spread to physical changes. Our dataset already contains those labels, so this is a practical comparison to run.

Produce: the learned directions, the appearance variation they explain, and errors on observations excluded from fitting. Compare them with the controlled azimuth/elevation/yaw responses before using either model to construct R.

Optional: interpreting the outputs

A rotated PCA axis is a valid description of spread. PCA alone does not attach physical angle labels to its axes; a separate mapping can add that connection. T-PLS components may also mix physical causes. Derive physical sensitivities from the fitted mapping, rather than simply naming its first loadings “azimuth” and “elevation.”

For a forward pose-to-appearance model, use pose features as inputs and tangent appearance changes as outputs. Predicting pose from appearance is also a useful diagnostic, but its coefficients are not the forward sensitivities. Local angular offsets are convenient in a small neighborhood; circular features can handle periodic angles over wider views.

Include examples where the physical inputs vary separately. Align tangent coordinates explicitly before pooling references. Start with two or three components, then inspect the unexplained variation. Keep complete vehicle identities and sequences separate when testing transfer.

3. Check that the uncertainty envelope matches actual errors

Use: a nominal reference view, nearby images with exact simulator geometry, and an example viewing-angle uncertainty. Begin with a simple case such as “azimuth is more uncertain than elevation.”

  1. Treat the nominal view as the tracker's estimated view. Choose an angle-error distribution around it.
  2. Draw many small angle offsets from that distribution. Render or select matching nearby views, using their actual geometry. The nominal view is the estimate; each sample's exact view is the simulated truth.
  3. Measure the same-vehicle embedding differences from the nominal reference. Compare that cloud with the uncertainty predicted from W and the chosen angle uncertainty.
  4. Repeat for different uncertainty levels and for models built using WC-TPCA and T-PLS. Use new samples rather than reusing the observations that fitted the models.

Produce: a plot of predicted envelopes over measured appearance differences, and the fraction of held-out differences inside the intended envelope. That fraction is its coverage.

Look for: an envelope that changes in the right directions and is neither consistently too tight nor unnecessarily broad. Retaining simulator truth lets us check the result even though we deliberately give the simulated tracker an uncertain view.

Optional: what this test does and does not simulate

Sampling viewpoints with corresponding images tests the local appearance-uncertainty bridge. Changing telemetry labels alone, while leaving all image geometry unchanged, would not generate those appearance differences. End-to-end testing can separately perturb the pose estimates supplied to the tracker, keeping the true generated camera/target poses for scoring.

For the full physical chain, draw camera pose errors and propagate them through the relative-view geometry. When a full appearance predictor exists, evaluate its actual residuals. With a fixed-reference predictor, also calibrate its unmodeled viewpoint variation from data. Estimate remaining crop, lighting, or occlusion error separately using controlled changes to those conditions.

Optional: what the score and gate mean

The squared Mahalanobis distance is zᵀ S⁻¹z, with S = P + R in this local identity-observation example. The illustrative 95% gate uses the 2D Gaussian threshold 5.991. A 127D tangent model needs a threshold for its own effective dimension.

A local Gaussian association score also includes log det S. This accounts for uncertainty volume, so widening a gate is not a free improvement. A complete MHT score also needs the appropriate detection, clutter, and hypothesis terms.

The isotropic baseline holds the lower noise level in both directions. This demo illustrates directional weighting, not a tuned benchmark. Compare fitted models at matched false-association rates in the actual experiment.

4. Test whether it helps the tracker keep the right identity

Use: the same held-out simulated detection sequences for every filter, including an orbit-and-climb trajectory, partial occlusion, and similar-looking distractor vehicles. Keep the true camera poses and vehicle identities for evaluation.

Do: supply estimated camera poses with controlled errors, then compare tuned vMF, isotropic tangent filtering, and tangent filtering using the WC-TPCA or T-PLS uncertainty models. Keep the detections and other tracker settings comparable.

Measure: whether tracks keep their true vehicle identity, how often they switch to a distractor, and how often one vehicle's track breaks into pieces. Compare retention at similar false-association rates, so simply accepting more candidates does not look like an improvement.

Produce: a side-by-side sequence review and a small results table. Once the benefit is clear on held-out simulations, check how well it transfers to real imagery and evaluate additional backbones.

The example learns a small number of directions from errors around one reliable reference. It retains error magnitudes and explicitly moves the envelope into the filter's coordinates.

Rank two is an example setting, not a discovered property. This version uses uncentered SVD of prediction errors, so it includes the energy of an unmodeled mean shift. Centered PCA instead describes variation around the sample mean. Neither makes a zero-mean noise model exact.

If calibration uses live tracker residuals, account for existing state uncertainty P before assigning all their scatter to R. Use a reliable reference and controlled data for the first experiment.

def calibrate_local_errors(reference, observations, rank=2, floor_std=0.03):
    """Learn a local error envelope around ONE reliable reference.

    Use same-vehicle samples from comparable conditions. Uncentered SVD
    captures expected squared prediction error, including unmodeled bias.
    This is an effective zero-mean uncertainty approximation, not a claim
    that the observed errors actually have zero mean. For centered PCA use
    V - V.mean(0); its variances are S_centered**2 / (N - 1).

    Different references/vehicles require explicit alignment and transfer
    validation before pooling. Training tracker residuals also contain P;
    assigning their full scatter to R would count that uncertainty twice.
    """
    mu = unit(reference)
    E = tangent_basis(mu)
    V = np.array([E.T @ log_map(mu, y) for y in observations])
    if len(V) < 2 or not 1 <= rank <= min(V.shape):
        raise ValueError("Need at least two samples and a supported rank")
    if not np.isfinite(floor_std) or floor_std <= 0:
        raise ValueError("Noise floor must be positive")
    _, singular_values, axes = np.linalg.svd(V, full_matrices=False)
    error_energy = singular_values[:rank] ** 2 / len(V)
    return {
        "mu": mu,
        "directions": E @ axes[:rank].T,
        "extra_variance": np.maximum(error_energy - floor_std**2, 0),
        "floor_std": float(floor_std),
        "mean_error": E @ V.mean(axis=0),
    }


def build_runtime_covariance_R(calibration, filter_mu, filter_basis):
    """Move a LOCAL learned envelope into the filter's current coordinates.

    Reusing an envelope far from its calibration neighborhood is an untested
    modeling assumption. Transport aligns coordinates; it does not establish
    that the same nuisance pattern applies at another viewpoint or identity.
    """
    moved = transport(calibration["mu"], filter_mu, calibration["directions"])
    U = filter_basis.T @ moved
    R = calibration["floor_std"] ** 2 * np.eye(U.shape[0])
    R += (U * calibration["extra_variance"]) @ U.T
    return covariance(R, U.shape[0], positive=True)


def pose_uncertainty_covariance(J, Sigma_pose, floor_std=0.03):
    """Optional J Sigma J.T propagation for uncertain pose, not orbit drift.

    J must contain actual local derivatives, with radians used consistently,
    in the SAME tangent basis as the filter. Do not normalize its columns.
    Pose covariance may have correlated entries. If pose is already part of
    a joint state/measurement model, avoid adding its uncertainty twice.
    """
    J = np.asarray(J, dtype=float)
    if J.ndim != 2 or not np.all(np.isfinite(J)):
        raise ValueError("Invalid sensitivity matrix")
    if not np.isfinite(floor_std) or floor_std <= 0:
        raise ValueError("Noise floor must be positive")
    Sigma_pose = covariance(Sigma_pose, J.shape[1])
    return J @ Sigma_pose @ J.T + floor_std**2 * np.eye(J.shape[0])


def local_pose_sensitivities(reference, perturbation_pairs, steps_rad):
    """One local sensitivity column per controlled physical input.

    perturbation_pairs contains (minus_embedding, plus_embedding) for each
    input, e.g. azimuth, elevation, yaw. Other rendering conditions should
    be held fixed. steps_rad contains the POSITIVE half-step for each pair.
    Returns (reference_mu, tangent_basis, J). Columns retain their scale;
    no independence or orthogonality of embedding effects is assumed.
    """
    mu = unit(reference)
    E = tangent_basis(mu)
    steps = np.asarray(steps_rad, dtype=float)
    pairs = list(perturbation_pairs)
    if steps.shape != (len(pairs),) or not len(pairs):
        raise ValueError("Supply one positive step per perturbation pair")
    if not np.all(np.isfinite(steps)) or np.any(steps <= 0):
        raise ValueError("Perturbation steps must be positive radians")
    columns = [
        E.T @ (log_map(mu, plus) - log_map(mu, minus)) / (2 * step)
        for (minus, plus), step in zip(pairs, steps)
    ]
    return mu, E, np.column_stack(columns)
